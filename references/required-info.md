# 用户需要提供的信息清单

当用户要求“支持某个平台采集”，但缺少商城地址、示例页面、接口或字段要求时，读取本文件，并向用户索要必要信息。

## 最少必要信息

优先只问最少能开工的问题：

1. 目标平台和国家 / 地区站点。
2. 一个搜索页或分类页 URL。
3. 一个商品详情页 URL。
4. 需要采集的字段清单。
5. 是否需要登录后才能看到目标字段。

示例提问：

```text
为了适配这个平台，请先给我：
1. 商城首页或目标站点地址
2. 一个搜索页/分类页 URL
3. 一个商品详情页 URL
4. 需要采集的字段
5. 这些字段是否需要登录后才能看到
```

## 如果用户有商品详情 API

让用户提供这些信息：

- 商品详情 API 地址。
- 请求方法：GET / POST。
- 示例完整请求 URL。
- 请求参数如何从商品 URL 或商品 ID 得到。
- 示例响应 JSON，敏感字段可打码。
- 是否需要登录态。
- 是否依赖 Cookie、Authorization、CSRF、签名、时间戳、设备参数。
- 响应字段对应关系，例如 `item.title -> title`。

提醒用户：

```text
请不要直接发送真实 Cookie、Authorization、token、账号 ID、设备指纹等敏感信息。
如果必须说明鉴权方式，请用已打码示例。
```

## 如果用户没有 API

让用户提供：

- 商品详情页 URL。
- 页面截图，标出要采集的字段位置。
- 如果可以，提供“查看网页源代码”中的相关片段或浏览器 DevTools 里字段所在节点。
- 是否是 SPA 页面，打开后是否需要等待加载。

Codex 应优先自己从项目和页面 HTML 中发现结构化数据，不要强迫用户抓包。

## 字段需求模板

可以让用户按下面模板填写：

```text
平台：
国家/地区：
商城首页：
搜索页示例：
商品详情页示例：
商品详情 API（如果有）：
是否需要登录：
需要字段：
- 标题
- 价格
- 币种
- 主图
- 全部图片
- 描述
- 销量
- 库存
- 上架时间
- 商家名称
- 商家ID
- 属性
- 变体
- 公开邮箱/电话（如页面公开展示）
导出格式：
- Excel
- JSON
并发要求：
备注：
```

## 判断是否可以先动手

可以先动手的情况：

- 用户给了项目代码和至少一个目标商品详情页。
- 用户给了明确平台、地区和字段。
- 现有项目已有相似平台 adapter，可按模式新增。

需要先问用户的情况：

- 只说“支持 Shopee/Temu”，没有地区或示例 URL。
- 要采集库存、销量、上架时间，但页面是否公开不清楚。
- 要使用详情 API，但没有 API 地址或响应示例。
- 需求涉及登录态、私有接口、token、风控参数。

## 不应索要的信息

不要索要或保存：

- 真实账号密码。
- 完整 Cookie。
- Authorization token。
- CSRF token。
- 设备指纹。
- 支付、地址、订单等私人信息。

如果调试确实需要用户描述登录态，要求用户打码，并优先使用浏览器当前会话而不是复制敏感信息。
